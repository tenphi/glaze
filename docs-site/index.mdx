## Color relationships, not color tables

Glaze turns a hue and saturation seed into a complete palette. Instead of
picking every color, you say how each color relates to the others. A **root**
color places itself with an absolute tone. A **dependent** color names a `base`
and sits a signed tone delta away from it, optionally with a contrast floor.
Glaze resolves the actual colors for every scheme.

<Example
  hue={280}
  saturation={80}
  colors={{
    surface: { tone: 97, saturation: 0.15 },
    'surface-2': { base: 'surface', tone: '-4', saturation: 0.2 },
    border: { base: 'surface', tone: '-10', saturation: 0.2 },
    'surface-text': {
      base: 'surface',
      tone: '-1',
      saturation: 0.4,
      contrast: 'AAA',
    },
  }}
/>

In dark mode the tone scale inverts, so `surface-2` and `border` step lighter
instead of darker, in the same order. The dark tone window scales the steps
down a little (about 3.5 and 8.7 tones here); the high-contrast variants keep
the exact 4 and 10. See
[how relative tone adapts](../docs/schemes.mdx#how-relative-tone-adapts).

## Contrast-aware by construction

Set a WCAG ratio or an APCA Lc floor on the colors that need one. Glaze keeps
the tone you asked for when it already passes, otherwise moves it about as far as
the floor requires, and warns when a color's floor can't be met (a
[mix](../docs/mixes.mdx#contrast-on-mixes) settles without a warning). Each tile
below measures the resolved colors in the scheme you're viewing.

<ContrastSamples
  hue={280}
  saturation={80}
  colors={{
    surface: { tone: 97, saturation: 0.15 },
    'surface-text-soft': {
      base: 'surface',
      tone: '-1',
      saturation: 0.3,
      contrast: 'AA',
    },
    'surface-text': {
      base: 'surface',
      tone: '-1',
      saturation: 0.4,
      contrast: 'AAA',
    },
    'accent-text': {
      base: 'surface',
      tone: '-1',
      contrast: { apca: 'body' },
    },
  }}
  samples={[
    { fg: 'surface-text-soft', bg: 'surface', note: "contrast: 'AA'" },
    { fg: 'surface-text', bg: 'surface', note: "contrast: 'AAA'" },
    {
      fg: 'accent-text',
      bg: 'surface',
      note: "contrast: { apca: 'body' }",
      metric: 'apca',
    },

/>

In high contrast, a floor without an explicit high-contrast value rises a tier:
`'AA'` becomes `'AAA'` and an APCA target gains 15 Lc. A numeric WCAG ratio
stays as written.

## Four schemes from one definition

Light, dark, light high-contrast, and dark high-contrast variants share one
model. Dark mode inverts tone (`100 − t`) and fits it into a dark tone window,
so the relationships you define survive the switch — there is no second palette
to maintain. High-contrast variants use the full tone range and the raised
contrast floors.

## A tone axis built for contrast

Glaze works in OKHST: OKHSL with lightness replaced by **tone**, an axis shaped
by WCAG luminance. Equal tone steps are equal contrast steps for neutrals and an
approximation for chromatic colors, so a delta like `'-8'` means the same
visible distance anywhere on the scale.

## Shadows and glows with exact steps

`shadow` and `glow` colors are translucent overlays — black for a shadow and
white for a glow by default. Glaze solves their opacity per surface, so once the
browser composites them the surface lands exactly `intensity` tones darker or
lighter: on light, dark, and chromatic surfaces alike, as long as the surface
has room for the step. A shadow can't go past black and a glow can't go past
white, so an out-of-reach step gets as close as it can and logs a console
warning: the card shadow at the top of this page disappears in dark high
contrast, where the page is already black (see
[unreachable steps](../docs/shadows-and-glows.mdx#unreachable-steps)). An
optional object color (`fg`) deepens or softens the step the way bounce light
does.

## Ready for applications and design tools

Export CSS custom properties, a Tailwind CSS v4 theme, W3C DTCG design tokens
(one file per scheme, or a single Resolver-Module document), plain JSON, or
[Tasty](https://tasty.style) bindings. Every tab below is the real output of the
theme in the first tab.

<ExportShowcase
  hue={280}
  saturation={80}
  colors={{
    surface: { tone: 97, saturation: 0.15 },
    'surface-text': {
      base: 'surface',
      tone: '-1',
      saturation: 0.4,
      contrast: 'AAA',
    },
  }}
/>

Glaze has zero runtime dependencies, is written in TypeScript with full type
definitions, ships tree-shakeable ESM and CommonJS builds, and runs in Node.js,
browsers, and edge runtimes.

## More in the box

- **Manual contrast level.** Put the normal palette on a 0–100 slider toward
  high contrast. Every level in between is solved, not approximated, and the
  high-contrast tier stays available on top. See
  [manual contrast level](../docs/schemes.mdx#manual-contrast-level).
- **Dark seed and per-color hue.** Give dark schemes their own hue and
  saturation seed, or shift one color's hue absolutely or relative to the seed.
  See [dark seed](../docs/schemes.mdx#dark-seed) and
  [hue and saturation](../docs/reference/color-definitions.md#hue-and-saturation).
- **Mixes.** Blend two colors in OKHSL or sRGB, opaque or transparent, with
  optional contrast solving. See [Mixes and transparency](../docs/mixes.mdx).
- **Brand colors.** Start a theme from a hex or RGB value with
  `glaze.fromHex()` / `glaze.fromRgb()`, or seed a single color from a literal
  value with `from`. See
  [fromHex / fromRgb](../docs/reference/theme.md#glazefromhexhex--glazefromrgbr-g-b)
  and [from](../docs/reference/color-definitions.md#from).
- **Standalone colors.** `glaze.color()` gives one color, or a pair with a
  contrast floor, the same scheme adaptation without a theme. See
  [Color tokens](../docs/reference/color-tokens.md).
- **Palettes.** Derive status themes with `extend()` and compose them into one
  prefixed token set with `glaze.palette()`. See
  [Designing a palette](../docs/methodology.mdx) and
  [Palettes](../docs/reference/palette.md).
- **Snapshots.** Export themes, color tokens, and palettes as JSON and restore
  them with `glaze.themeFrom()`, `glaze.colorFrom()`, and
  `glaze.paletteFrom()`. See
  [Exporting and integration](../docs/exporting.mdx).
- **Output formats.** Native `oklch()`, `rgb()`, and `hsl()`, plus Tasty's
  `okhsl()` and `okhst()`. See
  [color formats](../docs/reference/output.md#color-formats).

## Quick start

<CodeGroup
  label="Install Glaze"
  items={[
    { label: 'pnpm', language: 'shell', code: 'pnpm add @tenphi/glaze' },
    { label: 'npm', language: 'shell', code: 'npm install @tenphi/glaze' },
    { label: 'yarn', language: 'shell', code: 'yarn add @tenphi/glaze' },
  ]}
/>

```ts
import { glaze } from '@tenphi/glaze';

glaze.configure({
  modes: { dark: true, highContrast: true },
});

const theme = glaze(280, 80);

theme.colors({
  surface: { tone: 97, saturation: 0.15 },
  'surface-text': {
    base: 'surface',
    tone: '-1',
    saturation: 0.4,
    contrast: { apca: ['content', 'body'] },
  },
  border: {
    base: 'surface',
    tone: ['-8', '-16'],
    saturation: 0.2,
    inherit: false,
  },
  'accent-surface-text': { tone: 100, mode: 'fixed' },
  'accent-surface': {
    base: 'accent-surface-text',
    tone: '-1',
    contrast: 'AA',
    mode: 'fixed',
  },
});

const danger = theme.extend({ hue: 23 });
const palette = glaze.palette({ default: theme, danger });

const tokens = palette.tokens({
  prefix: { default: '', danger: 'danger-' },
});
// → {
//   light: { surface: 'oklch(...)', 'danger-surface': 'oklch(...)', ... },
//   dark: { ... },
//   lightContrast: { ... },
//   darkContrast: { ... },
// }
```

`border` is marked `inherit: false`, so the `danger` theme gets every color
except it.
