'@tenphi/glaze': minor
---

HDR glows. A glow can now go past SDR white: set `glowTuning.headroom` (globally, per theme, per color, or on `glaze.glow()`) to the number of stops above white it may use. A glow's own `tuning.headroom` merges over `glowTuning` field by field; a theme's `glowTuning` replaces the global one, as for the other tuning fields. When a glow's target tone (surface tone + `intensity × k`) passes 100, its resolved variant gains `hdr: { h, s, t, exposure }` — an opaque base, which is exactly what SDR already paints at its brightest (the pigment at full opacity, or a white surface no pigment can lift), plus a gain in stops. A glow whose pigment cannot lift a non-white surface at all (`reach: 0` on a gray surface, say) paints nothing in SDR and gets no HDR value either. The gain lands the exact step (a 12-tone glow on white reaches tone 112, `Y` 1.4631), capped so no channel passes `2^headroom`. It lands the whole step, so a full-reach glow starts at white as its target passes 100, while one with `reach` below 1 — pinned at its pigment, below white — jumps from that pigment to the exact step there. Every scheme uses the same headroom, high contrast included, and a manual `contrastLevel` interpolates `intensity` per pass as before.

- Nothing changes at the default `headroom: 0`: no variant carries `hdr`. With headroom set, the SDR variant (`h` / `s` / `t` / `alpha`) stays byte-identical, and so does every exporter's output until you opt in with `modes.hdr`.
- `glaze.formatHdr(variant, 'srgb-linear')` writes the HDR value as `color(srgb-linear R G B)` with a channel above 1 (e.g. `color(srgb-linear 1.4631 1.4631 1.4631)`), or returns `undefined` for a variant without one. `formatSrgbLinear` is exported for linear channels you build yourself.
- `headroom` must be a finite number ≥ 0, otherwise Glaze throws. Values above 2 clamp to 2 with a warning, since headroom counts stops, not a ratio (2 stops is 4× white); it prints once per field and value, and only after the whole `configure()` call, override, or color map has validated. A `headroom` on `shadowTuning` or a shadow's `tuning` throws.
- When HDR covers a glow's step, the "cannot reach" warning no longer fires for it. When the headroom cap leaves the step short, a new warning names the headroom and what it reached.
- `GlowTuning` is now its own interface (`LightingTuning` plus `headroom`); `ShadowTuning` is unchanged. New types: `ResolvedHdr`, `GlazeHdrFormat`; `ResolvedColorVariant.hdr` is optional. Snapshots stay at export version 2 and carry `headroom` through `export()` / `themeFrom()`.

HDR output is opt-in: `modes.hdr` (default `false`, globally via `glaze.configure({ modes: { hdr: true } })` or per call) adds the HDR values to every exporter, next to the SDR ones it already emits and only for the schemes the other modes include. HDR values are always `color(srgb-linear R G B)`, whatever `format`, and literal even under `splitHue`. Palette prefixes, the primary alias and collision filtering apply to them like any other entry.

- `tasty()`: a glow variant with an HDR value adds a key right after its SDR key, under the new `states.hdr` alias (default `'@media(dynamic-range: high)'`): `''`, hdr, dark, dark & hdr, hc, hc & hdr, dark & hc, dark & hc & hdr — only the keys that exist. Tasty gives later keys priority, so a dark key still beats the light HDR one.
- `css({ hdr: true })` (default: the global `modes.hdr`) adds `hdr: { light, dark, lightContrast, darkContrast }`. Each block is dense — every color with an HDR value in any scheme, its SDR declaration where that scheme has none — so wiring each one after the SDR blocks, under the same selector plus `(dynamic-range: high)`, can't leak a light HDR value into dark.
- `tailwind()` appends the same dense blocks after the SDR ones, under the new `hdrSelector` (default `'@media (dynamic-range: high)'`), combined with `darkSelector` / `highContrastSelector`.
- `tokens()` adds dense `lightHdr` / `darkHdr` / `lightContrastHdr` / `darkContrastHdr` maps, each right after its scheme; `json()` adds sparse `lightHdr` / … keys per color.
- `dtcg()` / `dtcgResolver()` keep `$value` SDR and put the HDR value in `$extensions['me.tenphi.glaze'].hdr` — `{ exposure, tone, base, value }`, with the opaque base as a DTCG sRGB color and the value as `srgb-linear` components that may exceed 1 — only in the scheme documents that have it.
- `glaze.color()` tokens are never glows, so the HDR options leave their output unchanged.
- New types: `GlazeCssSchemeBlocks`, `GlazeDtcgHdr`, `GlazeDtcgExtensions`. `GlazeConfigResolved.states.hdr` and `modes.hdr` are now always present.
